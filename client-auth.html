Who can do what in the gateway?

A Gateway Client is an agent-facing identity. An API key or MCP OAuth grant identifies the Client. The CLI, SDK, and MCP are ways to reach the gateway; they do not define the Client's permissions.

What each control means

Client capability

Provision connections

Allows this Client to discover integrations and create or remove gateway connections. Off by default for dashboard-created clients.

Client capability

Administer gateway

Allows this Client's key to manage clients, keys, profiles, and other administrative resources through HTTP. It does not create MCP admin tools.

Tool permission

Access profile

Lists the tools on existing connections this Client may use. The provisioning switch can be off while tool use still works.

Tool decision

Approval policy

Decides whether a permitted tool runs immediately or waits for a person. It does not grant access by itself.

Current local behavior

The built-in local Client currently has provision_connections and administer_gateway. Local i falls back to its key from gateway.json. ii uses a saved operator session first, but also falls back to that key. So i lacks admin commands, yet the credential available to it has admin authority.
